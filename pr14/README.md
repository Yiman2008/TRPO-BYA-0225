# Практическая работа №14 — аудит Vue-каталога

Каталог работы №13 с обработкой неполных записей, регрессионными проверками и измерением стоимости повторной фильтрации. Запускайте из полной копии репозитория.

```sh
npm install
npm run dev
npm test
npm run lint
npm run measure
npm run build
node scripts/build-report.js
npm run preview
```

## Сценарии из bug_cases.json

| Сценарий | Как воспроизвести в проблемном варианте | Что проверяет итоговая версия |
|---|---|---|
| B01 | Использовать фильтрацию отдельно для счётчика и списка | Оба используют один computed. Скрипт сравнивает число проходов |
| B02 | Менять статус непосредственно на prop карточки | Карточка отправляет ID. Модель заменяет запись, в тесте исходный объект заморожен |
| B03 | Назначить индекс ключом, затем убрать первый элемент фильтром | Ключ берётся из ID, порядок и ID проверяет тест |
| B04 | Передать broken_items.json без названия в фильтр по строке | Неполные записи получают имя «Без названия». Откройте ?state=broken |

B01–B03 проверяются как регрессии. В миграции №13 уже используются computed, события и стабильные ключи. Скрипт измерения моделирует повторный вызов фильтра в проблемном варианте и один вызов в исправленном.

## Замеры

`npm run measure` читает оба кейса из `performance_cases.json`, делает по 15 прогонов и выводит медиану времени фильтрации в Node.js. Сценарий на 1000 элементов сокращает число проходов с 2 до 1, сценарий с 50 переключениями — со 100 до 50. Измерение охватывает вычисление списка.

После сборки `node scripts/build-report.js` выводит размеры ресурсов. Для ручной проверки откройте preview и вкладки Network и Console, перезагрузите страницу, затем откройте `?state=broken`. Состояние проверки отмечено в [чек-листе](docs/quality_checklist.csv).
