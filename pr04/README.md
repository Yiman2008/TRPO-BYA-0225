# Практическая работа №4 — PHP. Основы языка, запросы и обработка HTML-форм

Небольшое PHP-приложение без MVC: таблица сотрудников из `employees.csv` с фильтром по отделу (GET), форма заявки нового сотрудника (POST) с серверной валидацией, сохранением введённых значений и безопасным выводом, а также автоматическая проверка сценариев из `form_cases.json`.

**Технологии:** PHP 8.1+ (проверено на 8.3), HTML5, CSS. Без фреймворков и базы данных.

## Запуск

Требования: установленный PHP 8.1 или новее (`php -v`).

```bash
cd pr04
php -S localhost:8000 -t public
```

Открыть <http://localhost:8000>. Вверху страницы видна строка «Версия приложения 1.0.0 · страница сформирована сервером <дата и время> · PHP 8.x» — значит, файл выполняется сервером, а не открыт как текст.

## Функции в `src/functions.php`

| Функция | Назначение |
|---|---|
| `e($value)` | экранирование через `htmlspecialchars(..., ENT_QUOTES, 'UTF-8')` |
| `mapEmployee($row)` | одна строка CSV → массив `id, name, department, experience, email` с приведением типов |
| `loadEmployees($path)` | чтение `employees.csv` через `fgetcsv` (разделитель `;`, удаление BOM), пропуск битых строк |
| `loadFormCases($path)` | чтение `form_cases.json` с `JSON_THROW_ON_ERROR` |
| `departmentsOf()`, `filterByDepartment()`, `averageExperience()` | список отделов, фильтр, средний стаж |
| `normalizeInput($_POST)` | `?? ''` для каждого поля, `trim`, защита от массивов вместо строк |
| `validateInput($input, $departments)` | серверная валидация, возвращает массив `поле => сообщение` |
| `buildApplication()` | превращает валидную заявку в запись таблицы |
| `runFormCase()` | прогоняет сценарий из `form_cases.json` через ту же валидацию |

Файл подключается в `public/index.php` через `require_once`.

## Форма и правила валидации

| Поле | Правило |
|---|---|
| `name` | обязательно, после `trim` и схлопывания пробелов — от 2 до 60 символов |
| `email` | обязательно, `filter_var(..., FILTER_VALIDATE_EMAIL)` |
| `department` | обязательно, только значение из списка отделов `employees.csv` |
| `experience` | обязательно, целое число от 0 до 50 (`FILTER_VALIDATE_INT` с `min_range/max_range`) |
| `comment` | необязательно, не длиннее 200 символов |

При ошибках над формой выводится список ошибок, у каждого поля — своё сообщение и красная рамка, введённые значения возвращаются в поля (экранированные). При успехе — подтверждение, новая строка подсвечивается в таблице сотрудников, форма очищается. Хранилища в этой работе нет, поэтому новая запись живёт только в ответе на этот POST.

## Отображение ошибок (шаг 15)

В начале `index.php`: `display_errors` включается только когда страница запущена встроенным сервером (`PHP_SAPI === 'cli-server'`), в этом случае в шапке видна метка «режим разработки». На обычном сервере ошибки не показываются пользователю. Найденное во время проверки предупреждение «Array to string conversion» для `?department[]=…` исправлено проверкой `is_string()`.

## GET и POST

- **GET** передаёт параметры в адресной строке (`?department=Разработка`). Запрос можно сохранить в закладки, повторить, отправить ссылкой; он не должен ничего изменять. Поэтому GET используется для фильтра.
- **POST** передаёт данные в теле запроса, их не видно в адресе, они не кешируются и не попадают в историю. Используется для отправки формы, которая создаёт новую запись.

## Зачем `htmlspecialchars`

Любые данные от пользователя (и даже из файлов) могут содержать символы `< > " ' &`. Если вывести их как есть, браузер воспримет `<script>` как настоящий тег, и выполнится чужой код (XSS), а кавычка в `value="..."` сломает атрибут. `htmlspecialchars($v, ENT_QUOTES, 'UTF-8')` превращает эти символы в сущности (`&lt;`, `&quot;` …), и браузер показывает их как текст. В проекте это функция `e()`, через неё проходит каждое выводимое значение.

## Путь данных от формы до HTML-ответа

1. Браузер отправляет `POST /` с полями `name, email, department, experience, comment`.
2. `index.php` определяет метод (`$_SERVER['REQUEST_METHOD']`) и вызывает `normalizeInput($_POST)` — `?? ''` + `trim`.
3. `validateInput()` возвращает массив ошибок; отделы для проверки берутся из `employees.csv`.
4. Нет ошибок → `buildApplication()` формирует запись, страница показывает подтверждение и новую строку таблицы. Есть ошибки → список ошибок и форма с прежними значениями.
5. Все значения выводятся в HTML через `e()`.
