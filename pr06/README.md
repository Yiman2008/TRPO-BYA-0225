# Практическая работа №6 — PHP. Работа с файлами, JSON, сессиями и подготовка к MVC

**Менеджер заметок**: читает записи из `data/notes.json`, позволяет добавлять заметки и отмечать выполненные (изменения сохраняются в тот же JSON), хранит выбранного пользователя из `users.json` в сессии и показывает его в шапке, проверяет сценарии из `session_scenarios.json`. Обработка запроса и HTML-шаблоны разнесены по разным файлам.

**Технологии:** PHP 8.1+, сессии PHP, JSON, HTML, CSS.

## Запуск

```bash
cd pr06
php -S localhost:8000 -t public
```

Открыть <http://localhost:8000>. Папка `data/` должна быть доступна PHP на запись (по умолчанию так и есть).

Вернуть заметки к исходному состоянию dataset: `git checkout -- data/notes.json`.

## Маршруты (шаг 2)

Все переходы идут через `public/index.php`:

| Запрос | Что происходит |
|---|---|
| `GET index.php` или `?page=notes` | список заметок + форма |
| `GET ?page=user` | выбор пользователя |
| `GET ?page=scenarios` | сценарии сессии |
| `POST ?action=add` | добавить заметку → redirect на `page=notes` |
| `POST ?action=toggle` (id) | переключить «выполнено» → redirect |
| `POST ?action=set_user` (user_id) | записать пользователя в сессию → redirect |
| `POST ?action=clear_user` | очистить выбор пользователя → redirect |
| `POST ?action=scenario` (scenario) | выполнить сценарий из session_scenarios.json → redirect |
| любой другой `page` / `action` | шаблон `404.php`, код ответа 404 |

**Что изменилось после шага 2:** раньше каждая страница могла бы быть отдельным PHP-файлом; теперь есть одна точка входа, которая по параметрам `page` и `action` решает, какой обработчик вызвать и какой шаблон подключить. Это прообраз маршрутизатора MVC: `page=notes` → будущий `NotesController::index()`.

## Файловое хранилище

- `loadJson($path)` читает файл через `file_get_contents` и декодирует `json_decode(..., JSON_THROW_ON_ERROR)`. Отсутствующий файл, ошибка чтения, синтаксическая ошибка JSON или не-массив превращаются в `StorageException` с понятным текстом.
- `saveJson($path, $data)` записывает `json_encode(JSON_PRETTY_PRINT | JSON_UNESCAPED_UNICODE)` через `file_put_contents(..., LOCK_EX)`.
- `loadNotes()` / `saveNotes()` используют только эти две функции — код работы с JSON не дублируется в обработчиках.
- Новая заметка: `title` после `trim` и схлопывания пробелов — от 3 до 100 символов; `id = max(id) + 1` (уникальный); `done = false`; `author` — имя пользователя из сессии или «Гость».
- **Ошибка данных (шаг 12):** если `notes.json` удалён или повреждён (например, `{bad`), `index.php` ловит `StorageException` и показывает `templates/error.php` с кодом 500 и сообщением «notes.json повреждён: Syntax error» / «Файл данных не найден: notes.json» — без fatal error.

**Ограничения:** весь файл читается и перезаписывается при каждом изменении (медленно на больших объёмах); при одновременных запросах возможна потеря изменений — `LOCK_EX` защищает только саму запись, а не цикл «прочитал → изменил → записал»; нет индексов, поиска и связей; файл должен быть доступен на запись веб-серверу; данные нельзя безопасно редактировать вручную во время работы. Для реального проекта нужна база данных.

## Session

- `session_start()` вызывается в самом начале `index.php`, до любого вывода HTML (иначе cookie не отправится).
- В `$_SESSION['user_id']` хранится **только id** выбранного пользователя; имя каждый раз берётся из `users.json`. По умолчанию — `null`, в шапке «Гость».
- Шапка (`layout.php`) показывает текущего пользователя и кнопку «Сбросить» (`POST action=clear_user`).
- Flash-сообщения кладутся в `$_SESSION['flash']` перед redirect и удаляются после показа.
- После каждого успешного POST — redirect с кодом 303 (Post/Redirect/Get), поэтому F5 не повторяет добавление заметки.

**Ограничения:** сессия живёт только в одном браузере и только пока жива cookie `PHPSESSID` и файл сессии на сервере; данные сессии теряются при закрытии приватного окна или очистке cookie; не подходит для долговременных данных — для них JSON/БД.

## Сценарии из `session_scenarios.json` (шаг 11)

На странице «Сценарии сессии» у каждого сценария есть кнопка «Выполнить», и видно текущее состояние сессии.

| Сценарий | Действие | Ожидается | Результат |
|---|---|---|---|
| `new_session` | очистка `$_SESSION`, `session_regenerate_id(true)` | `guest_or_default` | в шапке «Гость» |
| `set_name` (value = Student A) | найти «Student A» в users.json и сохранить его id | `stored` | в шапке «Student A», сохраняется после F5 и переходов |
| `clear` | `user_id = null` | `default` | снова «Гость» |

**Обычная вкладка и приватное окно.** Если в обычной вкладке выбрать Student A, а затем открыть приложение в приватном окне, там будет «Гость»: у приватного окна свои cookie, браузер не отправляет `PHPSESSID` из обычной вкладки, и сервер создаёт новую пустую сессию (сценарий `new_session`). При этом **заметки в обоих окнах одинаковые** — они лежат в общем файле `notes.json`, а не в сессии. Закрыв приватное окно, сессию оттуда теряем; выбор в обычной вкладке остаётся.

## Разделение обработчика и шаблона

- `index.php` читает параметры, вызывает функции из `src/`, меняет сессию, готовит массив данных и вызывает `render('list', [...])`.
- `render($template, $data, $status)` (в `helpers.php`) выставляет код ответа, через `extract` передаёт в шаблон только переменные из `$data`, рендерит шаблон в буфер и вставляет его в `layout.php`.
- Шаблоны в `templates/` только выводят готовые данные через `e()`. Они **не читают JSON и не меняют `$_SESSION`**.

**Ограничения:** маршрутизация — это `switch` в одном файле, который будет расти; шаблоны — обычный PHP без автоэкранирования; нет классов-контроллеров и автозагрузки. Это и есть подготовка к MVC: `switch ($page)` станет роутером, ветки — методами контроллеров, `src/notes.php` — repository/моделью, `templates/` — views.

## Сценарий проверки (что показать на защите)

1. `php -S localhost:8000 -t public` → в шапке «Пользователь: Гость», 2 заметки из `notes.json`.
2. Нажать «Добавить» с пустым полем → «Введите текст заметки». Ввести «Сдать ПР-06» → «Заметка добавлена…»; открыть `data/notes.json` — появилась запись `{"id": 3, …}`. Нажать F5 — заметка не задублировалась.
3. Кликнуть по квадрату у заметки #1 → она зачёркнута, в `notes.json` `"done": true`.
4. «Пользователь» → выбрать Student A → в шапке Student A; перейти между страницами, нажать F5 — значение сохраняется. «Сбросить» → снова Гость.
5. «Сценарии сессии» → выполнить new_session, set_name, clear по очереди — состояние меняется по колонке «Ожидается».
6. Открыть в приватном окне — там «Гость».
7. `index.php?page=abc` → страница 404.
8. Временно испортить `data/notes.json` (например, `{bad`) → страница «Не удалось загрузить данные»; вернуть файл командой `git checkout -- data/notes.json`.
