# Практическая работа №11

Перед рефакторингом создан тег `pre-pr11-refactor`. Итог — `pr11-complete` и `shop-v1.0.0`.

Проверены пространства имён и автозагрузка, зависимости конструкторов и разделение MVC. Введён Request для единой проверки строковых и целочисленных параметров. Неожиданные предупреждения PHP преобразуются в исключения; общий обработчик записывает подробности в журнал и показывает безопасный интерфейс 500. Добавлены заголовки CSP, nosniff, запрет iframe и кеширования страниц сессии.

Проверка реальными HTTP-запросами обнаружила конфликт имени переменной `$data` внутри View::render с данными формы. Параметр рендера переименован в `$variables`; тест теперь проверяет повторный вывод экранированного HTML и сохранение введённых значений.

Все пункты `architecture_checklist.csv` приведены с файлами реализации в README и проверяются `tests/architecture.php`. Маршруты и безопасность проверяются по исходным CSV/JSON через `tests/http.php`. В GitHub Actions добавлены lint и регрессионные проверки. В `.gitignore` исключены заказы, lock-файлы, журналы, локальная конфигурация и зависимости.

## Ответы для защиты

1. Приложение получает путь/метод HTTP, параметры фильтра, POST формы и данные сессии. Исходный ассортимент и сценарии находятся в `dataset/pr07..pr11`.
2. Repository преобразует JSON в модели, сервисы — модели и пользовательское состояние в рассчитанные результаты, Controller выбирает представление, View превращает подготовленные данные в HTML.
3. Проверены неизвестный маршрут/товар, пустая корзина, неверный email, отрицательное/дробное количество, неверный CSRF и HTML в имени. Контролируемые ошибки не превращаются в PHP warning.
4. При росте объёма следует заменить JSON на БД, реализовать транзакции заказа и остатков, авторизацию, пагинацию и фоновые уведомления.
5. После клонирования войти в `shop`, выполнить четыре команды проверки из README и запустить PHP с document root `public` и `public/router.php`.
6. Controller связывает HTTP со сценарием приложения; Model описывает предметные данные; View отвечает за HTML. Расчёты корзины и оформление вынесены в Service, доступ к данным — в Repository.
7. Router не формирует HTML, потому что его задача — сопоставить адрес и метод с действием. Благодаря этому маршрутизация проверяется отдельно от оформления страниц.
