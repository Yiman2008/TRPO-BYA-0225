# Практическая работа №10

Продолжение проекта, итоговый тег этапа — `pr10-complete`.

Последовательность: `GET /checkout → CheckoutController::index → форма с delivery_methods.json → POST /checkout → CSRF → OrderValidator → CheckoutService → OrderData → OrderRepository → очистка корзины → 302 /order/success → GET подтверждения`.

OrderValidator проверяет имя, обязательный email, необязательный телефон, способ доставки и обязательный адрес для курьера. Самовывоз выполняется из единственного учебного пункта выдачи, который указан в форме. Поэтому корректный сценарий `ok` из dataset не требует отдельного адреса. Неизвестная доставка не принимается. Ошибки возвращают 422, введённые значения нормализуются и экранируются при повторном выводе. Все POST-формы защищены CSRF-токеном.

OrderData создаётся только после проверки формы и непустой корзины. В JSON сохраняются номер, дата UTC, контактные сведения, доставка, снимок товарных строк и серверная сумма. Цена и состав не берутся из POST. Доставка прибавляется к сумме товаров. Заказы записываются в `var/orders.json`; исходное пустое состояние читается из `dataset/pr10/orders_seed.json`.

OrderRepository удерживает `flock` на отдельном lock-файле на время чтения и записи; сначала полностью пишет временный файл, затем заменяет основной через rename. При ошибке корзина не очищается, пользователю показывается 500, подробности остаются в журнале. Папка var исключена из Git и находится вне public.

Подтверждение доступно только в текущей сессии и содержит номер, сумму и способ доставки. Контакты и адрес на этой странице отсутствуют. Обновление подтверждения не создаёт повторный заказ, поскольку создание завершается redirect.

Проверки: `php tests/run.php`, `php tests/http.php`. Запуск — из `shop` командой `php -S 127.0.0.1:8000 -t public public/router.php`.
